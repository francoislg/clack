## Why

The trivia plugin currently treats all questions, answers, and cheats as one continuous stream. There is no notion of competitive "chapters" — a player who joined yesterday faces an all-time leaderboard dominated by veterans, and the channel never gets a satisfying close-of-chapter moment. Introducing optional **seasons** gives Slack workspaces a natural cadence (monthly by default, configurable), a reason for new joiners to engage, and a recurring finale moment without giving up the persistent identity and all-time record players have already built.

## What Changes

- Add a new optional config block: `trivia.seasons = { enabled: boolean, prompt: string }`. When disabled (the default), behavior is unchanged.
- Tag every newly-saved `question`, `answer`, and `cheat` record with a `season: string` field equal to the current season slug at write time. `users.json` and `categories.json` are untouched — players and the category pool span seasons.
- Introduce a new file `data/plugins/trivia/seasons.json` tracking `{ current, currentStartedAt, currentExpectedEndAt, history[] }`. Each history entry records `{ slug, startedAt, expectedEndAt, endedAt }` so a manual early-close can be distinguished from a scheduled end.
- Add a new MCP tool `check_season_status` that inspects the trivia reveal cron and `seasons.json` to return whether today's reveal is the last fire of the current season (deterministic — uses the same cron iterator that `create_scheduled_message` already relies on).
- Add a new MCP tool `start_new_season(slug, expectedEndAt)` available to **admin** role. Closes the current season (stamps `endedAt`), promotes a new slug + expected end into `current`. Callable both automatically (last fire of season) and on-demand by admins in any thread.
- Extend `retrieve_scores` to return per-user **current-season** and **all-time** totals. Add an optional `season` parameter — default `"current"`, accepts any historical slug or `"all"`.
- Extend `find_previous_questions` with an optional `season` parameter — default `"all"` so duplicate detection naturally scans across seasons (prevents re-asking July's question in August).
- Modify `PROCESS_RESPONSES_INSTRUCTIONS` so the reveal flow calls `check_season_status` early; when it is the season's last fire, the reveal renders an additional **season finale** section and calls `start_new_season` as its final step (after `retrieve_scores`, so the finale numbers reflect the season that just ended, not the new one).
- Modify the leaderboard table shape to a 3-row form: an empty top-left cell with player columns, a "Current Season" row, and an "All Time" row. Medals are awarded **independently per row** — current-season top 3 get medals on the Current Season row, all-time top 3 get medals on the All Time row. Column order: current-season descending.
- Add a boot migration that backfills `season: <initial-slug>` onto pre-existing entries the first time `seasons.enabled` is observed as `true`. The initial slug is generated by Claude from the `seasonsPrompt` and the current date.
- Update the `trivia-check` user instruction so admins discover that they can ask Clack to "start a new season" at any time.
- **Embed the category pool in each season**: extend `seasons.json` so `current` carries a `currentCategories: string[]` and each `history[]` entry carries a `categories: string[]`. When seasons are enabled, `get_ideas` reads `seasons.json#currentCategories` instead of the global `categories.json`. Each new season starts from the `categories.json` baseline (which serves as the persistent seed), optionally augmented with themed extras the admin/Claude pass at season-creation time. This unlocks themed seasons (e.g. "Marine Biology Month") and keeps category memory scoped to the active season.
- Extend `start_new_season` with an optional `themeExtras: string[]` argument. The new season's `currentCategories` is `unique([...categories.json, ...themeExtras])` — baseline plus themed augmentation. When `themeExtras` is omitted or empty, the new season uses just the baseline (a non-themed season).
- Extend `add_categories` and `remove_categories` with a `target: "current" | "default" | "both"` argument (default `"both"`). `"current"` only affects `seasons.json#currentCategories`; `"default"` only affects `categories.json` (the baseline that future seasons seed from); `"both"` affects both. When seasons are disabled, the `target` argument is ignored and both tools operate on `categories.json` (legacy behavior).

## Capabilities

### New Capabilities

- `trivia-seasons`: the season lifecycle — config schema, `seasons.json` shape, `check_season_status` + `start_new_season` tools, season tagging on writes, the season-finale section in reveal flow, the 3-row leaderboard rendering, admin-initiated rollover, and the enable-time backfill migration.

### Modified Capabilities

- `trivia-batch-answers`: `submit_answers` writes `season` onto each new answer/cheat. `retrieve_scores` returns both `currentSeasonCorrect` / `currentSeasonAnswered` and `totalCorrect` / `totalAnswered` per user, and accepts an optional `season` filter (default `"current"`, also accepts `"all"` or any historical slug).
- `trivia-question-search`: `find_previous_questions` accepts an optional `season` filter (default `"all"` — duplicate detection spans all seasons).
- `trivia-scheduled-prompts`: the reveal flow calls `check_season_status` near the top; when last-fire, renders a finale section above the leaderboard and calls `start_new_season` last; leaderboard rendering switches to the 3-row dual-totals shape.
- `trivia-cheating-detection`: `save_cheating` writes `season` onto each new cheat record. Cheater filtering in the reveal flow remains current-season-scoped (cheats from prior seasons do not silently exclude a player today).
- `trivia-categories`: `get_ideas` reads the active season's `currentCategories` when seasons are enabled (falls back to `categories.json` when disabled). `add_categories` and `remove_categories` gain a `target` argument. `start_new_season` seeds the new season's `currentCategories` from `categories.json` (baseline) plus optional `themeExtras` (themed augmentation).

## Impact

- **Code**: `src/plugins/trivia/` — new files for the two new tools, the migration, and the seasons data accessors; modifications to `submitAnswers.ts`, `saveQuestion.ts`, `saveCheating.ts`, `retrieveScores.ts`, `findPreviousQuestions.ts`, `scheduledPrompts.ts`, `types.ts`, `data.ts`, `index.ts`.
- **Config**: `data/config.json` gains an optional `trivia.seasons` block. Default behavior (omitted or `enabled: false`) is unchanged from today.
- **Data files**: `questions.json`, `answers.json`, `cheats.json` schemas gain a `season` field on each entry. New `seasons.json` file. `users.json` and `categories.json` unchanged.
- **Migrations**: one new boot migration (numbered next in the `src/migrations/` sequence) that backfills `season` onto existing entries the first time seasons is enabled.
- **Dependencies**: reuses the existing cron iterator that backs `create_scheduled_message` / `list_scheduled_messages`. No new packages.
- **Tests**: new tests for `check_season_status` cron-iteration logic (especially weekday-cron + weekend-end-of-month edge cases), `start_new_season` state transitions (auto vs admin-triggered), the migration backfill, and the dual-totals scoring math.
- **Backward compatibility**: fully backward-compatible when `trivia.seasons.enabled` is `false` or absent. No breaking changes for existing deployments.
