## Why

Today every trivia question is answered through public Slack reactions — `+1`/`-1` for boolean, `one`/`two`/`three`/`four` for choice. This works for closed-form questions ("True or false?", "Which of these four?") but excludes a whole category of open-ended questions ("What was the name of the song?", "Who wrote it?", "What year did it happen?"). Forcing those into a multiple-choice format flattens the difficulty, gives away the answer space, and removes the satisfying "I just knew that" beat from real trivia.

Free-form answers are the missing primitive. Players type their answer privately into a modal during the round; at reveal time a small fast Claude (Haiku) judges each submission against the question's expected/acceptable answers in one batched call. The reveal renders correct/incorrect voter lists exactly like choice and boolean — but with the player's typed text quoted alongside.

This depends on the in-flight `add-plugin-interactivity-sdk` change (the plugin needs `registerAction` and `registerView` to wire the `[Answer]` button → modal → submit flow) and follows `add-trivia-topical-questions` (the `answersFormat` rename and `{fact, topical}` axis must be in place before adding a third format value).

## What Changes

- **New `answersFormat` value — `"freeform"`**: a third option alongside `"boolean"` and `"choice"`. The generation flow rolls it from the same cascade tier weights; the reveal flow handles it as a parallel branch to the existing two.
- **New question-record fields (freeform-only)**: `expectedAnswer: string` (required, the canonical answer Claude wrote at generation time), `acceptableAnswers?: string[]` (optional variants Claude pre-enumerated), `gradingNotes?: string` (optional hint to the judge for tricky cases like "accept any major Canadian city").
- **New `SubmittedAnswer` field — `answerText?: string`**: carries the user's typed answer. The existing `answer | answerIndex` discriminator extends to `answer | answerIndex | answerText` exactly-one-of.
- **`SubmittedAnswer.correct` becomes optional**: `correct?: boolean` — `undefined` denotes "pending validation" (free-form rows written at modal-submit time, before the reveal-time Haiku judge). Readers of this field are tightened to ignore pending rows: leaderboard computation skips them entirely (does NOT count toward `totalAnswered`); history payloads emit `correct?: boolean` so Claude knows absence means "not yet scored."
- **New data-layer op — `updateAnswer(id, partial)`**: needed so the reveal flow can flip `correct` from `undefined` to the judged verdict without rewriting the whole row. Same on the global users namespace (no schema change there).
- **Trivia plugin registers Slack interactivity**: at plugin init, the trivia plugin calls `sdk.registerAction("freeform-answer:{questionId}", ...)` (RegExp form) for the `[Answer]` button click, and `sdk.registerView("freeform-modal:{questionId}", ...)` for the modal submission. Action handler opens the modal pre-filled with the user's pending answer (or empty if none). View-submit handler writes/updates the pending row via the new `updateAnswer` op.
- **`post_questions` Block Kit change**: when a posted question's `answersFormat === "freeform"`, the question card SHALL include a Slack button labelled `Answer` with `action_id === "plugin:trivia:freeform-answer:<questionId>"` (built via the plugin's prefix helper). No reactions are seeded on freeform questions (`deriveReactions` returns `[]` for freeform).
- **Modal lifecycle**: the modal SHALL show the question's statement read-only, a single-line text input, and (when the user has a pending answer) the pre-filled prior submission. Once `process_reveal_answers` has stamped the question's `processedAt`, opening the modal SHALL show a locked read-only view ("Answers are closed — yours was: …, verdict: …").
- **Inline Haiku judge in `process_reveal_answers`**: when processing a batch containing freeform questions, the tool SHALL invoke a small/fast model (Haiku 4.5) via a new `sdk.askClaude` helper, batching all freeform answers for that batch into a single prompt. The judge returns per-answer `{ correct: boolean, verdict: string }`. The tool then calls `updateAnswer` per row to commit the verdict, and includes the answers (with quoted `answerText`) in the reveal payload's voter lists. The judge prompt instructs Haiku to reject any answer that hedges between two or more distinct guesses (e.g., "Paris or London") as incorrect with reason `multiple-guess`, even if one guess matches — single-answer with qualifiers/parentheticals is fine.
- **New SDK method — `sdk.askClaude(opts)`**: a thin wrapper over the Anthropic SDK exposing a single-turn message creation primitive (model, system prompt, user prompt, max tokens). Used by the reveal flow's Haiku judge. The credential is reused from the existing Claude Agent SDK setup; no new env var.
- **`save_question` accepts the new fields**: required `expectedAnswer` when `answersFormat === "freeform"`; forbidden on boolean/choice. Optional `acceptableAnswers?: string[]` and `gradingNotes?: string` permitted only on freeform.
- **Scheduled prompts — 6-way matrix**: the generation flow already branches on `suggestedAnswersFormat × suggestedQuestionType` (2×2 from topical). Adding freeform makes it 3×2. The new `FREEFORM_FACT_FLOW_STEPS` and `FREEFORM_TOPICAL_FLOW_STEPS` paths instruct Claude to write the statement, the canonical `expectedAnswer`, and (optionally) `acceptableAnswers` for semantic variants Claude can think of.
- **Reveal payload — voter lists include `answerText`**: for freeform questions, `voters.correct[]` and `voters.incorrect[]` entries carry an `answerText: string` field so the renderer can quote each player's submission ("Bob said 'Paris' — correct! Alice said 'France' — also accepted.").
- **No new migration needed**: the change is purely additive — `answersFormat = "freeform"` is a new value, the new fields are all optional, and `correct: undefined` is interpreted by all readers as "pending" without needing a backfill of legacy rows (legacy rows always have `correct: boolean` set).

## Capabilities

### New Capabilities

- `trivia-freeform-questions`: The freeform answer format end to end — the new `answersFormat` value, the question-record fields specific to freeform (`expectedAnswer`, `acceptableAnswers`, `gradingNotes`), the `[Answer]` button + modal open/submit flow, the pending-answer storage shape (`answerText`, `correct: undefined`), the inline Haiku batch judge at reveal, the multi-guess rejection rule, and the reveal-payload extension (`answerText` on voter entries).

### Modified Capabilities

- `clack-plugins`: Adds `sdk.askClaude(opts)` to the plugin SDK — a single-turn Anthropic SDK helper that lets plugins make small/fast model calls without instantiating their own Anthropic client. Reuses the existing credential.
- `trivia-choice-questions`: Adds `"freeform"` as a valid value for `answersFormat` on `TriviaQuestion`, on `config.trivia.answersFormat` weights, and on the cascade (`SeasonEntry.answersFormat`, `SeasonFormatSlot.answersFormat`). The orthogonal `questionType` axis composes the same way (a freeform question can be `fact` or `topical`).
- `trivia-batch-answers`: `SubmittedAnswer` gains `answerText?: string`; `correct` becomes `correct?: boolean` (undefined = pending freeform); the leaderboard / score-retrieval / history readers tighten so pending rows do not count toward `totalAnswered` or `totalCorrect`. Data layer gains `updateAnswer(id, partial)`.
- `trivia-question-search`: `save_question` accepts `expectedAnswer` (required for freeform, forbidden otherwise), `acceptableAnswers?` (freeform only), `gradingNotes?` (freeform only); validates the discriminator (`answersFormat × these fields`) the same way it already validates `answersFormat × {isTrue, choices, correctIndex}`.
- `trivia-question-posting`: `post_questions` adds the `[Answer]` button on freeform question cards (action_id `plugin:trivia:freeform-answer:<questionId>`); skips reaction seeding for freeform.
- `trivia-reveal-processor`: `process_reveal_answers` runs the inline Haiku batch judge for any freeform questions in the batch, calls `updateAnswer` per row to commit verdicts, and emits voter lists that include `answerText` for freeform-question entries.
- `trivia-scheduled-prompts`: Generation matrix extended from 2×2 (`{boolean,choice} × {fact,topical}`) to 3×2 by adding `freeform`. New `FREEFORM_FACT_FLOW_STEPS` and `FREEFORM_TOPICAL_FLOW_STEPS` describe how Claude writes `statement`, `expectedAnswer`, and optional `acceptableAnswers` / `gradingNotes`.

## Impact

- **Stored data**: No migration. `data/plugins/trivia/games/*/questions.json` gains the new optional fields on new writes only. `data/plugins/trivia/games/*/answers.json` gains `answerText` on new freeform rows and allows `correct: undefined`. Legacy rows untouched.
- **Code**: `src/plugins/trivia/core/types.ts` (new fields), `src/plugins/trivia/core/dataLayer.ts` (new `updateAnswer` op), `src/plugins/trivia/domain/computeLeaderboard.ts` (skip pending rows), `src/plugins/trivia/tools/answers/submitAnswers.ts` (tighten filters), `src/plugins/trivia/tools/questions/saveQuestion.ts` (new validation paths), `src/plugins/trivia/tools/questions/postQuestions.ts` (freeform block builder + skip reactions), `src/plugins/trivia/tools/questions/getQuestionHistory.ts` (emit `correct?`), `src/plugins/trivia/tools/reveal/processRevealAnswers.ts` (Haiku batch + updateAnswer), `src/plugins/trivia/prompts/scheduledPrompts.ts` (new flow steps + matrix dispatch). New module `src/plugins/trivia/freeform/modal.ts` (Block Kit modal builder, open/submit handlers). New module `src/plugins/trivia/freeform/judge.ts` (Haiku prompt + parsing). `src/plugins/sdk.ts` gains `askClaude`.
- **External dependencies**: Uses the already-installed `@anthropic-ai/sdk` (a transitive dependency of `@anthropic-ai/claude-agent-sdk`); no new package. No new env var (the existing Anthropic API key is reused).
- **Configuration**: Existing `config.trivia.answersFormat` weights gain freeform support — admins set e.g. `{ boolean: 1, choice: 1, freeform: 1 }` to enable the format. Default remains `{ boolean: 1, choice: 0 }` (freeform off unless opted in).
- **User-visible behavior**: When no game has `freeform` weight > 0, behavior is identical to today. When enabled, players see freeform question cards with an `[Answer]` button instead of vote reactions; modal flow is private during the round, public quoted-answer voter lists appear at reveal.
- **Tests**: New unit tests for the modal handler (open with no pending → empty input; open with pending → pre-filled; open after reveal → locked), the Haiku judge prompt assembly + parsing, the multi-guess rejection rule, leaderboard skip of pending rows, `updateAnswer` data-layer op, and the 6-way prompt matrix dispatch. New integration test for the full freeform-fact flow (post → button click → modal submit → reveal → score updated).
- **Sequencing**: This change is opened only after BOTH `add-plugin-interactivity-sdk` and `add-trivia-topical-questions` have merged. Tasks reference the SDK methods from the first and the cascade machinery from the second.
