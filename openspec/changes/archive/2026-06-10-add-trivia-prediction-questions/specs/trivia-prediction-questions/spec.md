## ADDED Requirements

### Requirement: `prediction` questionType value

The trivia `questionType` axis SHALL accept a third value, `prediction`, mutually exclusive with `fact` and `topical`. A `prediction` question is generated by researching an UPCOMING real-world event (via `WebSearch`, capturing a `sourceUrl`) whose outcome is not yet known. It SHALL compose with every `answersFormat` (`boolean`, `choice`, `freeform`). The global default weight for `prediction` SHALL be `0`, so a game emits predictions only when its `questionType` cascade opts in.

#### Scenario: prediction composes with boolean

- **WHEN** `get_ideas` rolls `questionType: "prediction"` and `answersFormat: "boolean"`
- **THEN** generation produces a boolean claim about a future event and the question is saved with no `isTrue`

#### Scenario: prediction composes with choice

- **WHEN** `get_ideas` rolls `questionType: "prediction"` and `answersFormat: "choice"`
- **THEN** generation produces a choice question whose options cover the possible outcomes, saved with `choices` but no `correctIndex`

#### Scenario: prediction composes with freeform

- **WHEN** `get_ideas` rolls `questionType: "prediction"` and `answersFormat: "freeform"`
- **THEN** the question is saved with `freeformAnswerShape` but no `expectedAnswer` (the canonical answer is prepared at settle time)

#### Scenario: existing games never emit a prediction

- **WHEN** a game has no `questionType` override and `get_ideas` rolls the axis
- **THEN** the roll selects only from `fact` / `topical` (prediction weight is `0`)

### Requirement: Save composes static fields; the answer is a separate settle step

`save_question` SHALL compose only a question's STATIC fields (`composeStatic` per answer format: choice's `choices`, freeform's `freeformAnswerShape` + `judgeLeniency`; boolean adds none). The answer key SHALL be composed by a SINGLE path (`settleOutcome` per format) — applied IMMEDIATELY at save for a non-prediction (`composeWithKey` = static + settle), and DEFERRED for a prediction (saved with `resolved: false` and no key). Prediction questions therefore carry a `sourceUrl` and `resolved: false` at save and forbid any answer key in the save args.

#### Scenario: prediction saved without a key

- **WHEN** `save_question` receives a `prediction` question
- **THEN** the record is persisted with `resolved: false`, a `sourceUrl`, and no answer key
- **AND** if the save args carry an answer key, the tool returns an error (predictions are saved without an answer key)

#### Scenario: non-prediction behavior is unchanged

- **WHEN** `save_question` receives a `fact` or `topical` question with its answer fields
- **THEN** the composed record is byte-for-byte identical to the pre-prediction behavior (static composed, then the answer settled immediately from the same args)

### Requirement: `settle_question` answers a prediction or invalidates any question

A new admin-gated MCP tool `settle_question` SHALL decide a question's fate with EXACTLY ONE of:
- `outcome` — answers a pending prediction: validates the value through the same `settleOutcome` path, stamps the answer key + `resolved: true` + `resolvedOutcome` + `resolvedAt`. Errors if the target already has an answer key.
- `invalidate: true` + `invalidatedReason` — marks ANY question (any format/type, even an already-answered or already-revealed one) INVALIDATED: stamps `resolved: true` + `invalidated: true` + `invalidatedReason`, and CLEARS any verdicts on its answers so it scores 0 for everyone.

#### Scenario: answer a boolean prediction

- **WHEN** `settle_question` is called with `outcome: true` for a boolean prediction
- **THEN** the record gains `isTrue: true`, `resolved: true`, `resolvedOutcome`, and `resolvedAt`

#### Scenario: answering validates through the format

- **WHEN** `settle_question` passes an `outcome` that is not valid for the question's answer format
- **THEN** the tool returns an error and makes no change

#### Scenario: invalidate clears existing verdicts

- **WHEN** `settle_question` is called with `invalidate: true` + a reason on a question whose answers were already scored
- **THEN** the record gains `invalidated: true` + the reason, and every answer's verdict is cleared so it counts for 0

#### Scenario: invalidate requires a reason and is mutually exclusive with outcome

- **WHEN** `settle_question` is called with `invalidate: true` and no reason, OR with both `outcome` and `invalidate`, OR with neither
- **THEN** the tool returns an error and makes no change

### Requirement: Click verdicts on a keyless question are deferred

A vote click on a question with no answer key yet (a pending prediction) SHALL be persisted with `correct: undefined` (pending), so it is excluded from the leaderboard until the reveal derives the verdict from the settled key. This is owned by the answer-format handler (`resolveClick` returns an undefined verdict when the key is absent) — no consumer branches on questionType.

#### Scenario: pending prediction click is not scored

- **WHEN** a player clicks a vote button on a prediction that has not been settled
- **THEN** the answer row is saved with `correct: undefined`
- **AND** the leaderboard does not count it until the reveal derives the verdict
