## Why

The trivia plugin generates only text-prompted questions today. There is no way to ask "who is this?", "what landmark is this?", "what anime character is this?", "which album cover?", "from what video game?", or "what species is this?". A visual round — where the prompt is an image and the user picks from text choices — is a natural extension that doesn't require new answer-shape machinery (it reuses `choice` scoring) but does introduce a third orthogonal axis: the medium the prompt is delivered in.

`add-trivia-topical-questions` already factored the old single `type` field into two orthogonal axes (`answersFormat`, `questionType`) and established the cascade pattern for adding more. This change adds a third axis (`promptMedium`) using the same pattern. The combination matters: a photo of a recent newsworthy event is *both topical and visual*, and modeling visual as a value of `questionType` (`"visual"` alongside `"fact"`/`"topical"`) would forbid that combo. Treating it as an orthogonal axis preserves it.

**Image sourcing is multi-source from the start, not Wikipedia-locked.** Different subject categories have authoritative image sources: iNaturalist for species, TMDB for movies/TV, Cover Art Archive for albums, Jikan for anime/manga, Open Library for books, RAWG for video games, NASA for space, the Met for paintings, Wikipedia/Commons for landmarks/people/flags/history. A Wikipedia-only design works for ~half of the interesting visual categories and produces awkward fallbacks for the rest (e.g., Wikipedia main images for flags are SVG masters that have to be downloaded via their PNG thumbnail URLs; movies and albums hit copyright walls on Commons). `find_visual_subject` is structured as a pluggable source-registry router from v1 so the tool's contract doesn't change as new sources are added later.

A real concern unique to image-prompted questions: public image URLs leak the answer in the filename ("Eiffel_Tower.jpg" → giveaway). Slack's link unfurl and hover preview expose the URL even when the rendered card looks clean. This change mandates re-hosting images via Slack's `files.uploadV2` with a neutral filename so the asset is anonymous.

## What Changes

- **New axis — `promptMedium: { text: N, image: N }`** (default `{ text: 1, image: 0 }`). Cascades `slot → season → config → default` like `answersFormat` and `questionType`. Independent weighted roll in `get_ideas`.
- **New optional field — `TriviaQuestion.media`** — present iff `promptMedium === "image"`. Holds `{ kind: "image", url, altText, subjectId, title, license?, attribution?, slackFileId? }`.
- **`get_ideas` returns `suggestedPromptMedium`** as a third server-rolled axis. All four `image × {boolean, choice} × {fact, topical}` combos are permitted. Image+boolean uses a *claim-based* template (the image is evidence; the statement asserts an identity or property — e.g., "This is the flag of Ecuador. T/F"), while image+choice uses an *identification* template ("What is this?" + N candidate names).
- **Visual category pool — `data/plugins/trivia/visualCategories.json`** (new, optional flat `string[]`). When `suggestedPromptMedium === "image"`, `get_ideas` draws categories from this pool instead of the general one. When the visual pool is empty or missing, the server re-rolls `suggestedPromptMedium` to `"text"` (same fallback shape as topical's empty-context terminator). The seed list is broad enough to cover the multi-source ambition: people, landmarks, animals, plants, paintings, flags, world capitals, **movies, TV series, anime characters, video games, book covers, album covers**, space, classical art, currencies, sports figures.
- **New MCP tool — `find_visual_subject({ category, hint? })`** — a pluggable source-registry router. The tool resolves the right source(s) for the requested category, queries it, and returns the image **inline** (multimodal tool result) alongside `{ source, subjectId, title, imageUrl, license, attribution, summary }`. Returning the image bytes inline lets Claude actually see and evaluate the image during the research subflow (catches main-image quirks: diagrams instead of photos, baked-in captions that leak the answer, ambiguous subjects, watermarks). `subjectId` is source-namespaced: `tmdb:m-<id>`, `inaturalist:<taxon-id>`, `mbid:<uuid>`, `jikan:<id>`, `openlibrary:OL<id>`, `wikidata:Q<n>`, `wikipedia:<slug>`, `commons:File:<filename>`, `nasa:<id>`, `met:<id>`. The namespace is the dedup key — `find_previous_subjects` matches exact-namespaced-string only.
- **Pluggable image-source registry.** Sources are declared in `config.trivia.visualSources` (or the dedicated `data/plugins/trivia/visualSources.json`). Each source declares `{ name, categories: string[] | "*", requiresKey: boolean, keyConfigPath?: string, priority?: number }`. The default registry ships always-on keyless sources (Commons via thumbnail.source, Openverse, Cover Art Archive, Jikan, Open Library, NASA, Met OA) and *known-good* free-key sources that activate only when their keys are configured (iNaturalist, TMDB, RAWG). Admins enable opt-in sources by supplying API keys; the registry hot-resolves which sources are available at each `find_visual_subject` call.
- **New visual-research step: image inspection.** Claude SHALL inspect the inline image before writing any statement. Four checks: subject match (does the image depict what the metadata claims?), subject clarity (clearly visible? no obstruction?), answer leakage (no text overlays, captions, watermarks, or labels revealing the answer?), and distinguishing features (what's visually evident — informs distractor choice and identity-swap selection). Failures trigger a re-roll to a different candidate subject.
- **New MCP tool — `find_previous_subjects({ subjectId })`** — searches saved questions by `media.subjectId`. Statement-text dedup via `find_previous_questions` is useless for templated visual prompts ("Who is this?"); subject-level dedup is the right key.
- **Slack file-upload hop in `post_questions`** — when a question's `media.url` is an external URL and `media.slackFileId` is unset, `post_questions` downloads the upstream image and re-uploads via `files.uploadV2` with a neutral filename (`trivia-q-<questionId>.<ext>`), stamps `media.slackFileId` on the record, and references the Slack-hosted file in the rendered `hero_image`. Prevents URL/filename leak in Slack previews and unfurls.
- **`save_question` accepts new fields**: `promptMedium` (optional, validated against active weights), `media` (required when `promptMedium === "image"`, forbidden otherwise). No cross-axis restrictions on `answersFormat` × `promptMedium` — all four combos save.
- **`add_categories` / `remove_categories` gain `pool: "default" | "visual" | "both"`** (default `"default"`). Lets admins manage the visual pool with the same tools as the general pool, mirroring the existing `target: "current" | "default" | "both"` season pattern.
- **Six new prompt paths** in `SEND_QUESTIONS_INSTRUCTIONS` (covering `image × {boolean, choice, freeform} × {fact, topical}`): `visual+fact+choice`, `visual+fact+boolean`, `visual+fact+freeform`, `visual+topical+choice`, `visual+topical+boolean`, `visual+topical+freeform`. All share a common `VISUAL_RESEARCH_SUBFLOW` ("pick subject → call `find_visual_subject` → call `find_previous_subjects`"). After research, they split on `answersFormat`:
  - **Choice paths** write an identification prompt + N candidate names (subject's title at `suggestedCorrectIndex`, N-1 same-category-sibling distractors).
  - **Boolean paths** write a *claim-based* statement asserting identity/property about the image (distractor in the claim — identity-swap to a confusable subject, or image-grounded property claim for unique subjects).
  - **Freeform paths** write an identification prompt + typed text input — `expectedAnswer` is the subject's title from `find_visual_subject.result.title`; `acceptableAnswers` optionally enumerates observed variants (e.g., "Eiffel Tower" + "La Tour Eiffel"). No options to leak hints, no T/F polarity — the cleanest expression of "image IS the question."
  
  Topical variants additionally run WebSearch to anchor the subject in a recent event before fetching its image and save both `media` AND `sourceUrl`.
- **Governing principle: the image IS the question** (enforced in the prompt, not at storage). For image-medium questions to be valid, removing the image must break the question. A claim like "Birds have hollow bones. T/F" stays true regardless of which bird is shown — that's a text question with a decorative photo, not a visual question. Valid claims are about *this specific subject in this specific image*: identity ("This is the flag of Ecuador"), or properties that require identifying the subject first ("This bird is native to Europe" + Cardinal photo).
- **Reveal flow surfaces image attribution** — when a revealed question has `media`, the reveal includes a small "📷 Image: <attribution> · <license>" line. Honors Wikimedia license terms (CC-BY-SA typically requires attribution).
- **No migration.** `promptMedium` and `media` are optional, additive fields. Legacy records without `promptMedium` are read as `"text"` at every site. No rename, no stamping, no boot blocker.

## Capabilities

### New Capabilities

- `trivia-visual-questions`: the `promptMedium` axis (data, config cascade, server-rolled suggestion), the `media` field shape on `TriviaQuestion`, the visual category pool, the source-routing `find_visual_subject` tool, the pluggable visual-source registry, the `find_previous_subjects` tool, the Slack file-upload hop, and the visual-research prompt subflow.

### Modified Capabilities

- `trivia-categories`: gains the parallel `visualCategories` pool, and the `pool` argument on `add_categories` / `remove_categories`. The general `categories` pool is unchanged in shape.
- `trivia-question-search`: extends `save_question` validation to recognize `promptMedium` and `media`; enforces the `image ↔ choice` cross-axis rule; recognizes `media` as a saved field; introduces `find_previous_subjects` for subject-level dedup.
- `trivia-question-posting`: per-question/per-slot generation now dispatches on a 3-axis matrix `(answersFormat × questionType × promptMedium)` with two cells forbidden (`image + boolean × *`). `post_questions` performs the Slack file-upload hop and renders `hero_image` for image-medium questions. The reveal flow surfaces image attribution when present.
- `trivia-seasons`: `SeasonEntry` and `SeasonFormatSlot` gain optional `promptMedium` cascade fields alongside the existing `answersFormat` / `questionType` / `contexts`. `upsert_season` accepts them with the same mid-season-mutation semantics.

## Impact

- **Stored data**: no migration. New question records optionally carry `promptMedium` and `media`. Legacy records without `promptMedium` are read as `"text"`. Optional new file: `data/plugins/trivia/visualCategories.json` (seeded with defaults on first read when admin enables `promptMedium.image > 0` at any cascade tier; empty/missing reads as no visual pool, which triggers the server-side fallback to `text`).
- **Code**: `src/plugins/trivia/core/types.ts`, `src/plugins/trivia/core/dataLayer.ts`, `src/plugins/trivia/domain/promptMediums.ts` (NEW sibling to `questionTypes.ts`), `src/plugins/trivia/tools/questions/getIdeas.ts`, `src/plugins/trivia/tools/questions/saveQuestion.ts`, `src/plugins/trivia/tools/questions/postQuestions.ts`, `src/plugins/trivia/tools/categories/addCategories.ts`, `src/plugins/trivia/tools/categories/removeCategories.ts`, `src/plugins/trivia/prompts/scheduledPrompts.ts`. New `src/plugins/trivia/tools/visual/findVisualSubject.ts` (router) and `src/plugins/trivia/tools/visual/findPreviousSubjects.ts`. New `src/plugins/trivia/visualSources/` directory containing the shared `SourceAdapter` interface and one adapter file per source (`commons.ts`, `openverse.ts`, `coverArtArchive.ts`, `jikan.ts`, `openLibrary.ts`, `nasa.ts`, `met.ts`, plus key-gated `inaturalist.ts`, `tmdb.ts`, `rawg.ts`). New `src/plugins/trivia/visualSources/registry.ts` resolving the category → source mapping at request time. New `src/plugins/trivia/visualSources/types.ts` defining the adapter contract.
- **External dependencies**: a pluggable source registry. Default keyless sources: Wikipedia REST + Wikimedia Commons, Openverse, Cover Art Archive (MusicBrainz), Jikan (MAL proxy), Open Library, NASA Images, Met Open Access. Optional free-key sources: iNaturalist, TMDB, RAWG (activated only when their keys are configured in `data/auth/`). All sources are queried via HTTPS using built-in `fetch`; no new npm dependencies. Slack `files.uploadV2` is already used elsewhere (see `src/slack/handlers/homeTab.ts:877`); no new auth scope expected.
- **Configuration**: no breaking changes. Existing `config.json` files load unchanged. Admins opt into visual rounds by setting `promptMedium.image > 0` at any cascade tier AND populating `visualCategories.json`.
- **Tests**: full coverage for the two new tools (`find_visual_subject`, `find_previous_subjects`), the cross-axis validation in `save_question`, the file-upload hop in `post_questions`, the prompt branching, the `visualCategories` fallback, and the attribution rendering in reveal. Mock the Wikipedia/Commons HTTP layer.
- **User-visible behavior**: zero change when no game enables `promptMedium.image > 0`. With it enabled, occasional image-prompt questions in the trivia channel, with attribution shown on reveal.

## Dependencies

This change **depends on `add-trivia-topical-questions` and `add-trivia-freeform-questions` having shipped first** (both have at the time of writing):

- From topical: uses the `answersFormat` field name (renamed from `type`), the `questionType` axis (`fact | topical`), the `sourceUrl` / `eventDate` semantics (inherited on `visual+topical` records), and the `contexts` cascade slot.
- From freeform: uses the `answersFormat: "freeform"` value (a third answer-format on top of boolean/choice), the `expectedAnswer` / `acceptableAnswers` / `gradingNotes` fields on `TriviaQuestion`, the `[Answer]` button injection in `post_questions`, the `deriveReactions: []` behavior for freeform, the `answerText` field on `SubmittedAnswer`, and the reveal-time Haiku judge.
- Extends the same orthogonal-axes cascade pattern (`slot → season → config → default`) that both proposals established — `promptMedium` is the third axis using the identical cascade machinery.
